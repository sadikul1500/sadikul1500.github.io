Structural Design Pattern

Composite Pattern

The Composite Pattern lets the client treat one object and a whole hierarchy of objects in the exact same way through one shared interface.

Definition

  • Composite is about treating a single object and a massive group of objects in the same way.
  • It works best when data forms a tree or part-whole hierarchy.
  • Leaf objects and container objects both expose the same interface to the client.
  • The client sends one command without caring whether it reaches one item or an entire branch.

Problematic Scenario

Imagine a shipping system with products and boxes. A box can contain products, and it can also contain smaller boxes. The moment nested boxes appear, manual traversal becomes messy, repetitive, and fragile.

C# Manual traversal through nested boxes 
// 1. A simple item
public class Product
{
    public string Name;
    public int Price;
}

// 2. A complex item that holds things
public class Box
{
    public List<Product> Products = new List<Product>();
    public List<Box> SmallerBoxes = new List<Box>();
}

public class ShippingApp
{
    public int CalculateTotal(Box mainBox)
    {
        int total = 0;

        // PROBLEM: We have to manually traverse every layer!
        foreach (var product in mainBox.Products)
        {
            total += product.Price;
        }

        foreach (var smallBox in mainBox.SmallerBoxes)
        {
            foreach (var p in smallBox.Products)
            {
                total += p.Price;
            }

            // What if the small box has even SMALLER boxes?!
            // The code breaks unless we write endless nested loops!
        }

        return total;
    }
}

When to Apply Composite

  • Data is structured like a tree, with branches and leaves.
  • The client is forced to treat leaf objects and container objects differently.
  • We want the client to call something like GetPrice() without caring whether it is talking to one item or a huge branch.

Why This Gets Messy

Manual nested loops do not scale. Each new layer of nesting forces more traversal logic into the client. That makes the code harder to extend and couples the client to the exact internal structure of the tree.

Composite Pattern Solution

Introduce one common component interface for both products and boxes. A product returns its own price. A box loops through its children and asks each child for its price. Because both implement the same contract, the client can treat them uniformly.

C# Pseudocode Composite-based design 
// 1. Component Interface
IItem: GetPrice() -> int

// 2. Leaf
Product: IItem
{
    string name;
    int price;

    GetPrice() -> int
    {
        return price;
    }
}

// 3. Composite
Box: IItem
{
    List<IItem> items = new List<IItem>();

    Add(IItem item)
    {
        items.add(item);
    }

    GetPrice() -> int
    {
        int total = 0;

        foreach (item in items)
        {
            total += item.GetPrice();
        }

        return total;
    }
}

// 4. Execution
main()
{
    Product phone = new Product("Phone", 1000);
    Product charger = new Product("Charger", 50);
    Product headphone = new Product("Headphone", 200);

    Box smallBox = new Box();
    smallBox.Add(phone);
    smallBox.Add(charger);

    Box largeBox = new Box();
    largeBox.Add(smallBox);
    largeBox.Add(headphone);

    int finalPrice = largeBox.GetPrice();
}

Key Idea

The client speaks to everything through the same interface. A single product answers directly, while a box delegates the same request to its children and combines the result. That is what makes tree structures feel simple to use.

Benefits

  • Lets the client treat leaves and containers uniformly.
  • Works naturally with part-whole tree structures.
  • Removes fragile nested traversal logic from the client.
  • Makes recursive operations like pricing, rendering, and deletion easier to extend.
