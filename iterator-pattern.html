Behavioral Design Pattern

Iterator Pattern

The Iterator Pattern provides a standard way to move through a collection without exposing the collection's internal storage structure.

Definition

  • Iterator is about navigating data through a standard interface.
  • The client can move item by item without knowing whether the data is stored in an array, list, tree, stack, or buffer.
  • A TV remote is a useful example: pressing Channel Up does not reveal where the TV stores or receives channels.
  • The collection hides its structure and gives the client a simple traversal object.

Problematic Scenario

Imagine a music app that must play songs from different sources. A vinyl record stores songs in an array, while a Spotify playlist stores tracks in a list. The client now has to know both storage details just to play all music.

C# Client depends on storage details 
// Uses an Array
public class VinylRecord
{
    public string[] Songs = new string[] { "Track 1", "Track 2", "Track 3" };
}

// Uses a List
public class SpotifyPlaylist
{
    public List<string> Tracks = new List<string> { "Song A", "Song B", "Song C" };
}

// The Client
public class MusicApp
{
    public void PlayAllMusic(VinylRecord record, SpotifyPlaylist playlist)
    {
        // THE PROBLEM: The client has to know exactly how the data is stored!
        for (int i = 0; i < record.Songs.Length; i++)
        {
            Console.WriteLine(record.Songs[i]);
        }

        for (int i = 0; i < playlist.Tracks.Count; i++)
        {
            Console.WriteLine(playlist.Tracks[i]);
        }
    }
}

Detecting the Problem

If another team introduces a RadioStation that stores songs inside a complex tree or stack, the MusicApp must be opened again and given a third specialized traversal loop. The client keeps changing every time a new collection structure appears.

Iterator Pattern Solution

Give every collection a way to create an iterator. The iterator exposes only HasNext() and Next(), so the music player can traverse any music source without caring how the songs are stored.

Pseudocode Iterator-based traversal 
IIterator
    - HasNext()
    - Next()

IMusicCollection
    - IIterator CreateCollection()

ArrayIterator: IIterator
    - string item
    - position = 0
    - ArrayIterator(arraySong)
    - HasNext() => return position < arraySong.length
    - Next() => return arraySong[position++]

ListIterator: IIterator
    - string item
    - position = 0
    - ListIterator(listSong)
    - HasNext() => return position < listSong.length
    - Next() => return listSong[position++]

VinylRecord: IMusicCollection
    - arraySong = new Array({'track 1', 'track 2'})
    - CreateCollection() => return new ArrayIterator(arraySong)

ListRecord: IMusicCollection
    - listSong = new List(['track 3', 'track 4'])
    - CreateCollection() => return new ListIterator(listSong)

MusicPlayer
    - MusicPlayer(iterator)
    - PlayMusic()
      {
          while (iterator.HasNext())
          {
              Writeline('Playing now: ' + iterator.Next())
          }
      }

    - ListRecord lr = new()
    - MusicPlayer player1(vr.CreateCollection()), player2(lr.CreateCollection())
    - player1.PlayMusic()
    - player2.PlayMusic()

The Big C# Secret

This manual version helps us see the true Gang of Four architecture. In modern C#, we almost never write this from scratch because Microsoft built the Iterator pattern directly into the language and base library.

  • IEnumerator is the iterator, like the remote control.
  • IEnumerable is the collection, like the TV that can provide a traversal object.
  • A foreach loop is the Iterator pattern behind the scenes.

Key Idea

The client should not care whether data is stored in an array, list, tree, stack, or streaming buffer. It asks for an iterator and walks forward through one common interface.

Benefits

  • Hides the internal structure of a collection.
  • Lets different collections be traversed through the same interface.
  • Keeps client code from changing whenever a new storage type appears.
  • Makes traversal logic reusable and consistent.
