Structural Design Pattern

Decorator Pattern

The Decorator Pattern adds new behaviors to an object dynamically at runtime by wrapping it with small feature objects instead of creating endless subclasses.

Definition

  • Decorator is about adding new behaviors or features to an object dynamically at runtime.
  • It avoids feature growth through inheritance and uses wrapping instead.
  • The pattern says: stop using inheritance to add features, and start using composition.
  • Each decorator adds one focused responsibility while keeping the same interface as the wrapped object.

Problematic Scenario

A coffee ordering system starts simply, but each ingredient combination becomes a new subclass. As soon as more add-ons appear, the number of subclasses grows out of control.

C# Inheritance explosion for coffee combinations 
// The Base
public class SimpleCoffee
{
    public virtual string Description => "Simple Coffee";
    public virtual double Cost => 2.00;
}

// The Subclasses (PROBLEM: Inheritance Explosion)
public class MilkCoffee : SimpleCoffee
{
    public override string Description => "Simple Coffee, Milk";
    public override double Cost => 2.50;
}

public class SugarCoffee : SimpleCoffee
{
    public override string Description => "Simple Coffee, Sugar";
    public override double Cost => 2.25;
}

public class VanillaMilkSugarCoffee : SimpleCoffee
{
    public override string Description => "Simple Coffee, Vanilla, Milk, Sugar";
    public override double Cost => 3.50;
}

public class CoffeeApp
{
    public void Order()
    {
        // If we add a new ingredient like "Caramel", we have to create
        // many new subclasses to cover all the combinations!
        var myDrink = new VanillaMilkSugarCoffee();
    }
}

When to Apply Decorator

  • We have a rapidly growing number of subclasses just to handle different feature combinations.
  • We need to add or remove responsibilities to an object at runtime.
  • Inheritance is impossible because the class is sealed or final, but we still need extra behavior.

Core Shift

Decorator says: stop using inheritance, which models an is-a relationship, and start using composition, which models a has-a relationship. Instead of creating a new subclass for every combination, wrap one coffee object with additional feature objects.

Decorator Pattern Solution

Define one coffee interface, create a simple concrete coffee, then build decorators that hold an inner coffee object and add their own cost and description on top of it. Features can be layered in any order at runtime.

Pseudocode Decorator-based design 
ICoffee:
    GetDescription() -> string
    GetCost() -> double

SimpleCoffee: ICoffee
{
    GetDescription() => return "Simple Coffee";
    GetCost() => return 2.00;
}

abstract class CoffeeDecorator: ICoffee
{
    ICoffee _coffee;

    CoffeeDecorator(ICoffee c) => _coffee = c;

    virtual GetDescription() => return _coffee.GetDescription();
    virtual GetCost() => return _coffee.GetCost();
}

MilkDecorator: CoffeeDecorator
{
    // no variable is needed here
    MilkDecorator(ICoffee c): base(c) {}

    override GetDescription() => return base.GetDescription() + ", Milk";
    override GetCost() => return base.GetCost() + 0.50;
}

VanillaDecorator: CoffeeDecorator
{
    VanillaDecorator(ICoffee c): base(c) {}

    override GetDescription() => return base.GetDescription() + ", Vanilla";
    override GetCost() => return base.GetCost() + 0.60;
}

main
{
    ICoffee drink = new SimpleCoffee();
    drink = new MilkDecorator(drink);
    drink = new VanillaDecorator(drink);

    Console.WriteLine(drink.GetDescription() + " | $" + drink.GetCost());
}

Key Idea

A decorator keeps the same interface as the original object, but adds extra behavior before or after delegating to the wrapped object. That lets features be stacked one by one without changing the base class.

Benefits

  • Avoids inheritance explosion from feature combinations.
  • Adds or removes behavior dynamically at runtime.
  • Keeps each feature isolated in a small reusable class.
  • Works even when subclassing is not allowed.
