Creational Design Pattern

Abstract Factory Pattern

The Abstract Factory Pattern creates an entire family of related products through one master interface, keeping creation logic grouped and consistent.

Definition

  • Abstract Factory is essentially Factory Method applied to more than one product.
  • It works with a set of related products, also called a product family.
  • Create one master interface, the Abstract Factory, to build every product in that family.
  • It is useful when a system must guarantee that compatible products are created together.

Main Idea

Factory Method usually focuses on one product. Abstract Factory extends that idea so a single factory can create multiple related objects, such as a transport and its matching packaging. Instead of asking, "Which truck should I make?", the question becomes, "Which whole logistics family should I use?"

Problematic Scenario

The client creates both transport and packaging directly. This means the client is tightly coupled to multiple concrete classes at once, and it must keep those choices consistent.

C# Tightly coupled family creation 
public class LogisticsApplication
{
    public void PrepareShipment(string mode)
    {
        ITransport transport;
        IPackaging packaging;

        // TIGHT COUPLING
        if (mode == "Road")
        {
            transport = new Truck();
            packaging = new CardboardBox();
            // more code
        }
        else if (mode == "Sea")
        {
            transport = new Ship();
            packaging = new ShippingContainer();
        }

        transport.Deliver();
        packaging.Pack();
    }
}

Why This Becomes Difficult

  • The client knows too much about multiple concrete products.
  • Related objects must be selected together, which increases the chance of mismatch.
  • Every new family, such as Air or Rail, adds more branching logic in the client.
  • Creation logic and business workflow become mixed in the same method.

Abstract Factory Solution

Define a master factory interface that creates each product needed by the workflow. A road factory returns road-friendly products, while a sea factory returns sea-friendly products. The service uses the abstract factory and stays independent from concrete implementations.

Pseudocode Abstract Factory implementation 
ITransport: Deliver()
Truck, Ship: ITransport

IPackage: Pack()
Box, Container: IPackage

ILogisticFamily: CreateTransport(), CreatePackage()
RoadLogisticFamily, SeaLogisticFamily: ILogisticFamily

class LogisticFamilyService
{
    ITransport t;
    IPackage p;

    SetFamily(ILogisticFamily f)
    {
        t = f.CreateTransport();
        p = f.CreatePackage();
    }

    Shipment()
    {
        p.pack();
        t.deliver();
    }
}

main class
{
    LogisticFamilyService l = new();
    string mode;
    ILogisticFamily lf;

    if (mode == "road") lf = new RoadLogisticFamily();
    if (mode == "sea") lf = new SeaLogisticFamily();

    l.SetFamily(lf);
    l.Shipment();
}

Key Idea

Instead of creating one product through one factory method, the system selects one family factory. That factory then creates all related objects needed by the workflow. This keeps product combinations consistent and reduces client-side branching.

Difference from Factory Method

Feature Factory Method Abstract Factory
What does it make? One specific product, such as a transport. A family of related products, such as a transport and a box.
How does it work? Inheritance. A base class forces subclasses to override one creation method. Composition. An interface forces concrete factories to implement multiple creation methods.
Where is the business logic? Inside the creator. The base class runs the workflow and requests the product. Outside the factory. The factory only creates parts and an external service uses them.

Benefits

  • Keeps families of related objects consistent.
  • Reduces tight coupling to concrete implementations.
  • Makes it easier to introduce new product families later.
  • Separates object creation from shipment workflow logic.
