Singleton Pattern

The Singleton Pattern is about restriction: it ensures there is only one instance of a class in the entire application and provides a shared access point to it.

Definition

  • Singleton is entirely about restriction.
  • It ensures that a class has only one instance in the entire application.
  • It also provides a global point of access to that instance.
  • It is useful when a shared resource must never be controlled by multiple separate instances.

When We Need It

  • Use Singleton when a shared resource absolutely cannot have multiple controllers.
  • Use it when strict control over a global variable or global state is required.
  • It helps when every part of the system must read and update the exact same data state.

Core Rule

The usual structure is simple: make the constructor private, keep a private static instance field, and expose a public static method that returns that single shared object.

Problematic Scenario

Without Singleton, multiple services can create separate logger objects. That leads to tight coupling and makes a shared resource, such as a log file, harder to control safely.

C# Multiple services creating separate loggers 
public class Logger
{
    public void Log(string message)
    {
        // Code to open 'app.log' and write the message
        Console.WriteLine($"Writing to file: {message}");
    }
}

public class PaymentService
{
    public void Process()
    {
        // TIGHT COUPLING & RESOURCE DANGER
        Logger log = new Logger();
        log.Log("Payment processed.");
    }
}

public class EmailService
{
    public void Send()
    {
        // MULTIPLE INSTANCES
        Logger log = new Logger();
        log.Log("Email sent.");
    }
}

Why This Is a Problem

  • Every class can create its own instance of a shared resource.
  • The system loses strict control over a global state or file handler.
  • Client classes become tightly coupled to object creation.
  • Different instances may compete to manage the same underlying resource.

Singleton Pattern Solution

Restrict direct construction and force the application to request the logger through a shared access method. That method creates the object once and returns the same instance on every future call.

Pseudocode Singleton-based design 
public sealed class Logger
{
    private static Logger _logger;

    private Logger();

    public static Logger GetInstance()
    {
        if (_logger == null)
        {
            _logger = new Logger();
        }

        return _logger;
    }

    Log(string text): void
}

main()
{
    Logger l1 = Logger.GetInstance();
    l1.log(..);

    Logger l2 = Logger.GetInstance();
    l2.log(..);
}

Key Idea

Singleton does not focus on flexible creation. Instead, it focuses on preventing extra instances. The class itself controls access to its only object and guarantees that everyone uses the same shared instance.

Benefits

  • Guarantees that only one instance exists in the application.
  • Provides one consistent global access point.
  • Protects shared resources from uncontrolled multiple instances.
  • Makes sure all parts of the system see the same shared state.
