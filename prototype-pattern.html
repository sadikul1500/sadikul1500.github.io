Creational Design Pattern

Prototype Pattern

The Prototype Pattern creates new objects by copying an existing one instead of building every new object from the beginning.

Definition

  • Prototype creates new objects by copying an existing object.
  • Create exactly one fully initialized object, the prototype, and clone it when more are needed.
  • It is useful when construction is expensive and many objects are mostly identical.
  • It also helps hide complex setup logic from client code.

Main Idea

Instead of repeatedly calling a costly constructor, the application prepares one master object and duplicates it. The clone receives the same initialized state, which avoids paying the full setup cost every time.

Problematic Scenario

Imagine a video game that must spawn an army of 1,000 Orc enemies. If creating one Orc requires expensive loading of models, scripts, and animation data, repeatedly calling new Orc() can freeze the game.

C# Expensive object creation for every enemy 
public class Orc
{
    public string Name;
    public int Health;
    public byte[] Heavy3DModel; // Pretend this is massive

    public Orc(string name)
    {
        Name = name;
        Health = 100;

        // THE PROBLEM: Expensive Initialization
        Heavy3DModel = new byte[1000000];
    }
}

public class GameLevel
{
    public void SpawnArmy()
    {
        // Spawning 1,000 will freeze the game.
        Orc orc1 = new Orc("Warrior");
        Orc orc2 = new Orc("Warrior");
        Orc orc3 = new Orc("Warrior");
    }
}

When to Consider Prototype

  • Creation is expensive.
  • Objects are mostly identical.
  • We want to hide creation complexity from the rest of the code.

Prototype Pattern Solution

Build one master copy fully, then duplicate it through a Clone() method. The clone can reuse expensive data that is already prepared, and client code can create more objects without knowing the details of the heavy initialization process.

Key Idea

The system pays the expensive setup cost only once. After that, new objects are produced through copying. This makes bulk creation faster and keeps the client away from the details of heavy initialization.

Benefits

  • Reduces the cost of creating repeated complex objects.
  • Works well when many objects share the same initial state.
  • Hides construction complexity from the client.
  • Makes object creation faster in scenarios such as games, templates, and configuration copies.
